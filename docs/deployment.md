# Развёртывание

Приложение собирается как статический сайт для GitHub Pages. Для публикации нужен принадлежащий пользователю репозиторий GitHub и отдельное подтверждение публикации; в этом репозитории удалённый адрес пока не настроен.

## Локальная проверка

Из корня проекта выполните:

```powershell
npm ci
npm run typecheck
npm test -- --run
npm run test:e2e -- --project=chromium
npm run build
```

Сборка включает локальные JS/CSS-чанки, математические библиотеки, графику, иконки и Service Worker. Workbox формирует versioned precache по содержимому файлов; новый Service Worker ожидает явного действия пользователя «Обновить приложение». Сторонние API и удалённые runtime-скрипты не требуются.

## GitHub Pages

Для корневого домена соберите приложение с базовым путём `/`. Для репозитория `owner/repository` перед сборкой задайте `BASE_PATH=/repository/`, например в PowerShell:

```powershell
$env:BASE_PATH = "/repository/"
npm run build
```

Опубликуйте содержимое `dist/` как артефакт Pages из HTTPS workflow. В настройках репозитория выберите **Settings → Pages → Build and deployment → GitHub Actions**. Сборка и публикация должны запускаться только после настройки принадлежащего пользователю репозитория и его явного разрешения.

Перед публикацией проверьте, что страницы, manifest, иконки и `sw.js` обслуживаются по HTTPS и под префиксом репозитория; затем пройдите [чек-лист iPhone Safari](./iphone-acceptance.md).
